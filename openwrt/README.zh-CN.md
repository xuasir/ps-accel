# PS Accel：OpenWrt 主路由串流增强

基准环境为已验证原方案有效的 **FastRhino R66S / rockchip/armv8 / OpenWrt 25.12-SNAPSHOT / Linux 6.12.115**。本套件在原有提码率链路上重做管理、诊断与部署，服务与配置均独立命名为 `ps-accel`。

## 当前功能（0.1.9）

三个一级入口分别为 **设备配置、码率增强、透明代理**，支持手机、深浅色和键盘导航。

页面按运行状态、配置、日志排列。设备 LAN 网桥、代理域名与端口直接展示；日志默认展开，文本日志固定 240 px 高度并滚动，域名清单限制高度。设备、节点与日志使用可搜索的悬浮选择列表，滚动和窗口变化时跟随控件定位，刷新时保留正在查看的选项。节点直接读取本机 PassWall UCI；连接诊断归入日志区域，页面优先显示当前问题与下一步操作。透明代理提供独立的“开机启用”开关，默认开启，设置变化保持当前代理状态。

| 一级功能 | 操作阶段 | 能力 |
| --- | --- | --- |
| 设备配置 | 确认与保存 | 从 DHCP 租约 / 邻居选择 Portal、PS5 的内网 IPv4 地址，确认 MAC，两项功能共用这组设备 |
| 码率增强 | 运行、配置与日志 | 目标码率与中继地址、质量采集与降档建议、保存后启动、换档重启与恢复、独立任务和增强事件 |
| 透明代理 | 节点与启停 | 动态认证 / 信令泛匹配、指定节点、域名规则与端口、预览与热更新、实际出口与会话证据、分阶段检测、固件直连、停用与回滚 |

- 设备地址保存独立于码率中继，透明代理与域名采集可在码率增强停止时使用。
- 35 / 45 / 65 / 100 / 200 Mbps 档位，运行中保存码率自动恢复与重启。
- 有界短窗口采集客户端报告丢失、坏帧／关键帧请求、中继接收队列丢包和转发处理耗时，提供只读降档建议。
- 保存设备与中继配置后可启动常驻增强，环境检查与网络恢复直接展示；使用提示随运行、采样延迟和恢复状态更新。
- 透明代理复用已有 PassWall / Sing-box，按设备、域名规则与 TCP 端口匹配；动态认证 / 信令自动覆盖，代理目标保留原有直连和阻断条件，固件主机名可显式直连。
- 代理配置与已应用配置分别显示，预览绑定当前环境，首次接入或切换节点保留共享重启确认。
- 域名访问归属透明代理日志，展示认证 / 信令 / API 分类、DNS / TCP / TLS 可见证据、当前草稿归属与本轮新增；配置页可批量补充观测到的必要主机名。
- 日志内可加入代理或排除清单；调整写入草稿，保存、预览与应用完成后进入运行配置。
- 日志与诊断按核心连接记录展示实际出口、双向字节与连接阶段；连接异常时可检测认证、信令、Google 和固件直连。
- 连接失败回溯保留前 180 秒 / 后 15 秒证据与最近 32 次失败，域名清单按 MAC 保存。
- 设备、码率增强、透明代理各有任务结果与日志；增强诊断、代理诊断分别导出。
- 后台记录采用有界队列和日志轮转，独立观察服务支持采集开关与排查标记。
- UCI / LuCI 权限、后台任务互斥、子进程超时、取消、失败回滚与网络清理重试。
- 构建同时生成 IPK、脚本安装包和可直接打开的独立交互预览 HTML。

## 在 R66S 上安装

构建安装文件：

```sh
python3 openwrt/build.py
```

`openwrt/release-assets/` 会生成通用脚本安装包、opkg IPK、`SHA256SUMS` 和独立交互预览 `ps-accel-console-0.1.9.html`。

对于截图中的 25.12 系统，优先使用脚本安装包。安装器自动识别 `apk` 或 `opkg`，依赖从主路由当前固件的软件源获取。

先在原提码率插件中停止服务、完成恢复并关闭开机启动，然后上传 `ps-accel-openwrt-0.1.9-1.tar.gz` 到路由器 `/tmp`。在路由器执行：

```sh
cd /tmp
tar xzf ps-accel-openwrt-0.1.9-1.tar.gz
cd ps-accel-openwrt
sh install.sh
ps-accel doctor
```

依赖已经安装时，可使用 `sh install.sh --offline`。脚本安装保留在本机，使用包内的 `uninstall.sh` 管理卸载；`apk` 数据库登记依赖包。原生应用 APK 由下方的固件构建流程生成。

使用 opkg 的系统可安装 `ps-accel_0.1.9-1_all.ipk`：

```sh
opkg update
opkg install /tmp/ps-accel_0.1.9-1_all.ipk
```

内核模块依赖由当前固件软件源解析，`kmod-veth` 版本需与本机内核匹配。程序采用 Python 与 LuCI JavaScript，IPK 的 `all` 表示这些文件独立于 CPU 架构。

已有脚本安装版升级时，进入新安装包目录，停止并卸载旧版后安装。卸载默认保留 UCI、设备配对和测试数据：

```sh
cd /tmp/ps-accel-openwrt
python3 app/portal_openwrt.py stop
sh uninstall.sh
sh install.sh --offline
```

第一条命令使用新包的控制器完成停止恢复，可以处理旧版删除了一部分网络资源的情况。清理失败时保留资源归属记录并报告原因，处理完成后再次执行该命令。

## 设备配置

LuCI → **服务 → PS Accel → 设备配置**。

1. 保持两台设备开机，在地址旁点击“选择 Portal / PS5”，或手动填写各自内网 IPv4 地址。
2. 设备列表支持搜索和刷新；LAN 网桥直接显示，默认使用 br-lan。
3. 点击“保存设备配置”，确认地址属于所选网桥，且分别对应独立 MAC。结果和配置日志留在本页。
4. 在 OpenWrt 设置 DHCP 静态租约，保持码率增强使用的 IPv4 地址稳定。

设备配置保存到 UCI 与 `/etc/ps-accel/devices.json`，码率增强、透明代理和域名采集共用。保存设备地址直接确认 LAN 身份；码率增强的中继独立地址在其配置区域设置。更换设备前停止码率增强、完成网络恢复，并停用透明代理；地址或 MAC 变化后重新保存设备与码率增强配置。同一设备重复确认保留已有有效配对。

已有版本的 `auto-config.json` 可提供初始共享设备身份，新的码率配对会同步共享设备记录。

## 码率增强

进入 **码率增强**，选择目标码率和同一 LAN 的空闲中继地址，例如主路由为 `10.0.0.1` 时使用 `10.0.0.250/24`。实际地址以 DHCP 规划为准，避开主路由与动态地址池。点击“保存配置”，完成地址探测与码率中继配对。

在页面中完成以下流程：

1. 保存设备地址与码率增强配置。
2. 在顶部“运行状态”点击“启动增强”，本次启动会保存开机启动选项。
3. 重新连接 Portal，检查画面与按键。运行区展示增强状态、目标码率、连接计数、控制转发与质量采样；环境检查、停止与网络恢复直接操作，日志默认展开。

运行中调整档位，在页面选择新码率并点击“保存并自动重启”。后台依次停止旧中继、恢复网络、保存档位并启动新中继，状态与阶段反馈留在本功能。任务完成后重新连接 Portal；启动失败时尝试恢复原档位并重启。中继停止时，“保存码率”保存下次连接所用的请求值。

启动依据已保存的地址、码率和设备身份，运行中继续校验局域网配置与恢复状态。日志详细程度、采集开关、排查标记与透明代理配置分别管理。

命令行 `ps-accel profile` 用于停止后的单独保存；LuCI 管理任务负责运行中的自动重启流程。

### 轻量质量采集与降档建议

增强或连接测试运行时，在既有 Portal → PS5 单向中继中读取客户端回传反馈。固定 12 秒窗口按 `Σ丢失 / Σ(接收 + 丢失)` 计算比例，并合并控制消息重传；客户端报告可能包含多种媒体或经过限幅。视频回程保持设备直达，实际视频码率、帧率与端到端延迟继续以客户端观测为准。

初始建议要求至少 6 秒跨度、连续 6 个完整秒都有有效反馈、每秒至少 50 个媒体包且合计至少 600 个。每秒报告丢失达到 3%，或每秒达到 1% 且至少两个秒内出现坏帧／关键帧请求时，建议试用下一低档：200 → 100 → 65 → 45 → 35。阈值属于初始参考，需要 R66S / Portal 实测校准；瞬时波动继续积累证据。

建议保持只读，并绑定中继已观察到的当前档位新连接请求。增强启动前已经建立的串流先采集质量并提示重连。用户在码率配置中选择推荐档位并保存，重连 Portal 后比较相同游戏场景。35 Mbps 持续异常时优先改善无线信号与 AP 争用；连接测试仅采集。新握手重置客户端窗口，反馈中断超过 5 秒会重新积累证据；断开、格式待适配、样本不足和过期数据分别展示。

Linux 每 2 秒读取当前接收套接字的 `PACKET_STATISTICS`，丢包与客户端报告分开统计；中继队列丢包或超过 5% 的转发处理样本耗时达到 5 ms 时，优先提示检查路由器负载与并行任务。处理 p95 使用固定直方图上界估算，覆盖收包后到发送及采集完成的用户态耗时，套接字等待、Wi-Fi 空口与完整串流延迟各有独立测量范围。

采集只保留固定大小的内存窗口与去重键，状态由既有后台队列每 2 秒写入。采集异常时转发与恢复继续运行。增强诊断仅导出聚合计数与建议；原始载荷只用于当次识别，内存去重标识随进程结束释放，设备配置沿用现有脱敏边界。

```sh
ps-accel configure --bridge br-lan --address 10.0.0.250/24 \
  --ps5 10.0.0.100 --portal 10.0.0.101 --profile 65
ps-accel baseline
ps-accel try --seconds 90
ps-accel stop
ps-accel profile --profile 100
```

## 透明代理

进入 **服务 → PS Accel → 透明代理**。Portal 与 PS5 沿用“设备配置”确认的身份，设备默认网关保持 OpenWrt。

1. 点击“选择代理节点”，搜索并选择本机 PassWall 的 Sing-box 节点。列表显示节点不可用的具体原因，点击“刷新节点”重新读取。
2. 按需要调整“开机启用”。启用后的代理按此偏好恢复；调整开关保持当前代理状态。关闭时当前会话继续使用已应用规则，重启后使用原 PassWall 策略。
3. 点击“启用透明代理”，程序自动检查规则。同节点更新直接应用；首次接入或换节点时，在当前页勾选 PassWall 重启确认，再次点击启用。
4. “域名与端口”默认折叠，包含代理域名、排除域名、TCP 端口和检查结果。普通主机名、full: 前缀与 *.example.com 均可使用，每份清单最多 32 条；动态认证 / 信令内置覆盖。需要先存草稿时点击“保存配置”。
5. 在“连接与诊断”查看实际出口、连接和分阶段检测；在“日志与诊断”查看域名、启用日志及导出结果。日志中的域名调整进入草稿，点击启用应用当前配置。

按 **设备地址 AND（完整主机名 OR 泛匹配规则）AND TCP 端口** 匹配，作用于现有透明 TCP 入口。代理范围中的原有直连与阻断条件优先执行，完整主机名与泛匹配排除规则优先于代理规则，其他连接沿用原规则顺序和默认出口。`dwc.dl.playstation.net` 命中排除清单时，为两台设备的 TCP 80 / 443 生成直连规则并保留原阻断条件；其余排除域名返回原策略。

内置规则沿用 relay 的动态分类条件：`*.auth.np.ac.playstation.net` 归为认证；`*.np.communication.playstation.net`、`gsconnect.*`、`*.gsconnect.playstation.net`、包含 `signaling` 的主机名和 `*.remoteplay.playstation.net` 归为信令。规则通过 Sing-box 的后缀、前缀正则和关键词字段匹配，已有完整主机名配置在规则刷新后自动获得动态覆盖。预览显示内置规则；域名日志和核心会话使用同一匹配范围判断覆盖及排除状态。

节点支持 Shadowsocks、Trojan、VLESS、VMess、Hysteria2、TUIC、AnyTLS、SOCKS 和 HTTP 的普通 Sing-box 配置。链式节点、自定义节点 DNS、ShadowTLS、ECH 和其他特殊配置在首版节点列表中过滤。

**首次接入、旧版诊断入口迁移与换节点会重启共享 PassWall，现有网络连接可能重连。** 同节点修改主机名、端口和设备地址通过本地规则集热更新；停用清空代理与固件直连规则集。核心进程继续运行，已有连接使用原出口直到结束。应用失败会恢复此前配置；恢复启动失败时页面保留“PassWall 恢复待检查”。

核心连接接口使用配置中的回环地址与本机凭据。新增检测入口仅监听 `127.0.0.1`，从 `18780–18843` 分配端口，两个认证用户分别走所选节点与原直连。已有回环控制器的完整配置保留；新增控制器使用随机凭据。安装依赖包含 `ca-bundle`，用于 TLS 证书验证。

地址跟踪服务每两秒采样核心连接，最多保留 128 条设备 TCP 连接。实际命中要求当前配置、设备地址与最近 15 秒的有效证据；API 读取失败保留连接历史，切换配置或设备后等待新的记录。AUTH / SIGNALING / CONNECTED 阶段按域名与传输推断，真实登录和短连接覆盖结合终端验证。

固定检测通过所选节点访问认证、信令和 Google，通过原直连访问固件主机名 TCP 80。DNS 结果来自路由器解析器，CONNECT / TLS 结果来自指定检测出口；结果显示检测时间，配置变化后标为此前配置。取消在目标之间生效，码率服务继续运行。固件直连规则按完整主机名匹配，固件文件与终端升级结果通过设备验收。

防火墙与 DNS 的接管范围由原 PassWall 控制。全局客户端代理或目标端口位于接管范围之外时，预览给出阻止原因；启用设备 ACL、域名/IP 旁路或 IPv6 旁路时，页面显示覆盖提示，设备实际入口需在 PassWall 核对。域名识别依赖现有核心提供的 DNS 信息或可见 SNI，同一 HTTPS 主机与端口下的业务共享规则精度。

配置位于 `/etc/ps-accel/psportal/`，地址跟踪服务为 `ps-accel-policy`。服务每 10 秒读取现有租约与邻居；当前地址待发现时，其匹配范围为空。DHCP 静态绑定和终端身份配置由现有网络管理。卸载撤销插件所属的生成器扩展，保留空规则集供活动核心使用；后续 PassWall 重启生成原配置。

IPv4 TCP 重定向的精确出口、热更新、停用和回滚已在同固件用户空间的隔离容器验证。TProxy / IPv6 实流量、终端登录和实际串流在真实 R66S 验收，详情见 [0.1.4 验证记录](../docs/verification-0.1.4.zh-CN.md)。

## 运行反馈与诊断

“目标码率”表示启动请求，“控制转发”表示 Portal → PS5 的中继流量采样。PS5 → Portal 视频沿用设备直达路径。实际画质与视频吞吐通过真实游戏与设备观测评估。

“导出诊断”生成本地 JSON，包含版本、平台、运行计数、测试有效性、恢复状态、域名清单和失败证据。导出保留公共解析地址，并遮盖本地地址与设备 MAC；原始任务日志与会话报文保留在路由器。

```sh
ps-accel status
ps-accel doctor
ps-accel stop
ps-accel repair
logread -e ps-accel
```

`ps-accel stop` 会等待主控、引擎与恢复进程退出，完成恢复后返回。procd 保留独立恢复进程的时间窗口；错误状态会保留恢复路径供检查。

LuCI 停止任务共享 120 秒期限，页面显示停止、等待退出和恢复清理阶段。清理失败后任务进入失败状态，错误原因保留在页面和诊断中；“恢复网络”会再次校验仍存在的命名空间及接口归属，从中断步骤继续。状态查询出错时，停止与恢复入口仍可重试。

动态状态每 3 秒刷新，命名空间存在时执行一次有 2 秒期限的进程查询。配置与基线在首次加载、操作后或配置、程序变化时重新读取校验；启动前执行完整基线校验。各功能的日志阶段可见时按所选类型读取：设备、增强和代理任务输出分别保存，中继事件末尾最多 12000 字节，域名视图读取有界快照。简洁模式每 10 秒刷新日志，详细模式每 2 秒刷新日志；状态继续每 3 秒刷新。

转发循环把事件和统计快照提交到内存队列，后台线程负责文件写入。日志队列保留 128 条，每条最多 4096 字符；积压时舍弃旧记录，统计快照持续合并为最新值。事件日志每份最多 1 MiB，保留 2 份备份，路径为 `/tmp/ps-accel/events.log`。关闭中继时，诊断线程最多等待 0.2 秒。

“增强状态”依据进程启动身份、命名空间和本次启动的就绪标记。“记录状态”展示日志与统计的健康信息；写入失败或采样陈旧时，已就绪的中继继续显示运行，采样值显示为延迟。设备恢复凭据、恢复标记与引擎就绪信息由控制流程同步保存，保存失败时启动流程完成清理并报告错误。

## 日志策略、域名访问与失败回溯

在“码率增强 → 日志与诊断 → 日志设置”或“透明代理 → 日志与诊断 → 域名日志设置”选择详细程度并保存。默认 **简洁** 模式保留中继启停、码率修改握手和异常，重复事件按分钟合并，统计与域名快照每 10 秒更新；**详细** 模式每 2 秒更新快照，保留每次可见域名事件，适合复现问题期间使用。日志策略由后台刷新，保存后在 10 秒内应用，中继保持运行。

**“记录 PS5 / Portal 域名访问”是独立采集开关，默认开启。** 修改开关后点击“保存域名日志设置”：关闭时释放采集套接字，观察进程进入空闲状态，已有域名清单和失败记录保留；重新开启后继续采集。该服务独立命名为 `ps-accel-observe`，中继停止期间也能记录设备访问，采集开关与中继开机启动分别管理。

在“透明代理 → 日志与诊断 → 域名访问”查看已配对设备的域名、首次 / 最近出现、解析成功、DNS 错误码、TCP 握手响应、连接拒绝和观测超时。支持输入域名筛选、仅看最近异常和选择历史失败。域名最多保留 512 个设备 / 域名组合，超过容量时轮换最早闲置项；清单按设备 MAC 绑定，设备更换后重新配对。清单定期写入 `/etc/ps-accel/domains.json`，跨重启保留已保存结果；新域名保存间隔为 60 秒，常规计数为 5 分钟，关闭采集时也提交保存。

设备升级前，在“排查标记”填写新版本名并保存，例如 `Portal 升级 4.0`。随后首次出现的域名显示“本轮新增”；更新日志模式或采集开关时，同一标记的起始时间继续保留。此标记用于比较首次观测时间与升级时间。

设备报错时，在“透明代理 → 日志与诊断 → 连接失败回溯”填写错误码或现场描述，点击“记录这次失败”。系统保存失败前 180 秒、后 15 秒的域名证据，按异常次数排列候选域名；成功访问保留为上下文。重复摘要与内存明细合并时，每次异常计数一次；超出明细容量时优先保留异常，并标出精简和覆盖受限情况。中继、恢复与后台管理任务的失败也会自动加入记录。最近 32 次失败持久保存，每次证据最多 64 KiB。

采集在 LAN 网桥使用内核报文过滤，按已配对设备的 MAC / IPv4 地址匹配，IPv6 按 MAC 匹配。内核筛选 DNS、TCP 建连、可见 TLS ClientHello 和 ICMP 错误；观察服务使用低优先级、有界缓存、每秒 500 包上限和后台文件写入。域名事件位于 `/tmp/ps-accel/domains.jsonl`，每份最多 256 KiB，保留 2 份备份；高频原始事件保存在内存和 `/tmp`，持久清单合并写入。

诊断依据可见网络证据：DNS 错误码表示解析返回错误；观测超时表示观察窗口内缺少响应；共享 IP 对应多个候选域名。加密 DNS、TLS ECH、分段 ClientHello、硬件加速和采集限速会影响覆盖；HTTPS 内部业务错误需结合设备提示确认。覆盖时间、采集丢弃、解析错误与写入错误显示在域名视图，便于判断证据完整程度。

## 集成到 25.12 固件或 SDK，生成原生 APK

将本目录完整复制到与你的 R66S 固件同版本的 OpenWrt 构建树 `package/ps-accel/`，选择 `Network → ps-accel`，然后执行：

```sh
make package/ps-accel/compile V=s
```

`Makefile` 使用 OpenWrt 的 `BuildPackage`，包格式跟随目标构建树；25.12 的 apk 构建树生成原生 APK。SDK 的固件版本和软件源应与 R66S 当前固件一致。
