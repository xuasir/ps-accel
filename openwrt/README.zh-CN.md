# PS Accel：OpenWrt 主路由串流增强

基准环境为已验证原方案有效的 **FastRhino R66S / rockchip/armv8 / OpenWrt 25.12-SNAPSHOT / Linux 6.12.115**。本套件在原有提码率链路上重做管理、诊断与部署，服务与配置均独立命名为 `ps-accel`。

## 当前功能（0.1.10）

四个一级入口依次为 **设备配置、码率增强、透明代理、域名监控**，支持手机、深浅色和键盘导航。

页面按运行状态、配置、日志排列。设备 LAN 网桥和两份 PassWall 域名名单直接展示；日志默认展开，文本日志固定 240 px 高度并滚动，域名清单限制高度。设备与日志使用可搜索的悬浮选择列表，刷新时保留正在查看的选项。透明代理使用 PassWall 设备专属访问控制与独立分流规则组，绑定已确认的 Portal / PS5；直连优先，代理名单使用本机已有出口，其余默认直连。

| 一级功能 | 操作阶段 | 能力 |
| --- | --- | --- |
| 设备配置 | 确认与保存 | 从 DHCP 租约 / 邻居选择 Portal、PS5 的内网 IPv4 地址，确认 MAC，两项功能共用这组设备 |
| 码率增强 | 运行、配置与日志 | 目标码率与中继地址、质量采集与降档建议、保存后启动、换档重启与恢复、独立任务和增强事件 |
| 透明代理 | 两设备专属接管 | 设备 ACL、独立分流规则组、现有出口引用、全部直连与解除接管，兼容 Xray 与 Sing-box |
| 域名监控 | 连接批次与解析记录 | 自动分批、手动新建批次、全部域名与失败解析筛选、纯域名复制、批次流量与代理流量排序、加入或移出代理清单、持久历史与失败回溯 |

- 设备地址保存独立于码率中继，透明代理与域名采集可在码率增强停止时使用。
- 35 / 45 / 65 / 100 / 200 Mbps 档位，运行中保存码率自动恢复与重启。
- 有界短窗口采集客户端报告丢失、坏帧／关键帧请求、中继接收队列丢包和转发处理耗时，提供只读降档建议。
- 保存设备与中继配置后可启动常驻增强，环境检查与网络恢复直接展示；使用提示随运行、采样延迟和恢复状态更新。
- 透明代理按设备 MAC 建立专属访问控制，域名规则写入独立分流组，Xray / Sing-box 配置由 PassWall 原生生成。局域网地址与默认出口直连，代理规则按完整主机名精确匹配。
- 保存设备草稿与应用接管分别执行。应用在隔离的 UCI 副本中校验，检查配置与设备身份版本后原子写回；失败恢复所属设备配置，已有节点与全局域名名单保留。
- 域名监控按连接批次展示认证 / 信令 / API 分类、DNS 地址与 TTL、错误码、TCP / TLS 证据、当前草稿归属与本轮新增；域名行可快捷加入设备代理名单，移出时转入设备直连名单；应用设备规则后生效。
- 域名记录内可一键加入或移出代理清单，全部域名和失败域名按每行纯域名复制，适用于 PassWall 普通规则列表；调整写入草稿，预览与应用完成后进入运行配置。移出泛匹配或动态覆盖的域名时，为该主机名添加精确排除规则。
- 日志与诊断按核心连接记录展示实际出口、双向字节与连接阶段；连接异常时可检测认证、信令、Google 和固件直连。
- 连接失败回溯保留前 180 秒 / 后 15 秒证据与最近 32 次失败，域名清单按 MAC 保存。
- 设备、码率增强、透明代理各有任务结果与日志；增强诊断、代理诊断分别导出。
- 后台记录采用有界队列和日志轮转，独立观察服务支持采集开关与排查标记。
- UCI / LuCI 权限、后台任务互斥、子进程超时、取消、失败回滚与网络清理重试。
- 构建同时生成 IPK、脚本安装包和可直接打开的独立交互预览 HTML。

## 在 R66S 上安装

构建安装文件：

```sh
python3 openwrt/build.py
```

`openwrt/release-assets/` 会生成通用脚本安装包、opkg IPK、`SHA256SUMS` 和独立交互预览 `ps-accel-console-0.1.10.html`。

对于截图中的 25.12 系统，优先使用脚本安装包。安装器自动识别 `apk` 或 `opkg`，依赖从主路由当前固件的软件源获取。

先在原提码率插件中停止服务、完成恢复并关闭开机启动，然后上传 `ps-accel-openwrt-0.1.10-1.tar.gz` 到路由器 `/tmp`。在路由器执行：

```sh
cd /tmp
tar xzf ps-accel-openwrt-0.1.10-1.tar.gz
cd ps-accel-openwrt
sh install.sh
ps-accel doctor
```

依赖已经安装时，可使用 `sh install.sh --offline`。脚本安装保留在本机，使用包内的 `uninstall.sh` 管理卸载；`apk` 数据库登记依赖包。原生应用 APK 由下方的固件构建流程生成。

使用 opkg 的系统可安装 `ps-accel_0.1.10-1_all.ipk`：

```sh
opkg update
opkg install /tmp/ps-accel_0.1.10-1_all.ipk
```

内核模块依赖由当前固件软件源解析，`kmod-veth` 版本需与本机内核匹配。程序采用 Python 与 LuCI JavaScript，IPK 的 `all` 表示这些文件独立于 CPU 架构。

已有脚本安装版升级时，进入新安装包目录，停止并卸载旧版后安装。卸载默认保留 UCI、设备配对和测试数据：

```sh
cd /tmp/ps-accel-openwrt
python3 app/portal_openwrt.py stop
sh uninstall.sh
sh install.sh --offline
```

第一条命令使用新包的控制器完成停止恢复，可以处理旧版删除了一部分网络资源的情况。清理失败时保留资源归属记录并报告原因，处理完成后再次执行该命令。

## 设备配置

LuCI → **服务 → PS Accel → 设备配置**。

1. 保持两台设备开机，在地址旁点击“选择 Portal / PS5”，或手动填写各自内网 IPv4 地址。
2. 设备列表支持搜索和刷新；LAN 网桥直接显示，默认使用 br-lan。
3. 点击“保存设备配置”，确认地址属于所选网桥，且分别对应独立 MAC。结果和配置日志留在本页。
4. 在 OpenWrt 设置 DHCP 静态租约，保持码率增强使用的 IPv4 地址稳定。

设备配置保存到 UCI 与 `/etc/ps-accel/devices.json`，码率增强与域名采集共用。透明代理以这组已确认的设备 MAC 作为访问控制范围。保存设备地址直接确认 LAN 身份；码率增强的中继独立地址在其配置区域设置。更换设备前停止码率增强、完成网络恢复，并在透明代理解除设备接管；地址或 MAC 变化后重新保存设备与码率增强配置。同一设备重复确认保留已有有效配对。

已有版本的 `auto-config.json` 可提供初始共享设备身份，新的码率配对会同步共享设备记录。

## 码率增强

进入 **码率增强**，选择目标码率和同一 LAN 的空闲中继地址，例如主路由为 `10.0.0.1` 时使用 `10.0.0.250/24`。实际地址以 DHCP 规划为准，避开主路由与动态地址池。点击“保存配置”，完成地址探测与码率中继配对。

在页面中完成以下流程：

1. 保存设备地址与码率增强配置。
2. 在顶部“运行状态”点击“启动增强”，本次启动会保存开机启动选项。
3. 重新连接 Portal，检查画面与按键。运行区展示增强状态、目标码率、连接计数、控制转发与质量采样；环境检查、停止与网络恢复直接操作，日志默认展开。

运行中调整档位，在页面选择新码率并点击“保存并自动重启”。后台依次停止旧中继、恢复网络、保存档位并启动新中继，状态与阶段反馈留在本功能。任务完成后重新连接 Portal；启动失败时尝试恢复原档位并重启。中继停止时，“保存码率”保存下次连接所用的请求值。

启动依据已保存的地址、码率和设备身份，运行中继续校验局域网配置与恢复状态。日志详细程度、采集开关、排查标记与透明代理配置分别管理。

命令行 `ps-accel profile` 用于停止后的单独保存；LuCI 管理任务负责运行中的自动重启流程。

### 轻量质量采集与降档建议

增强或连接测试运行时，在既有 Portal → PS5 单向中继中读取客户端回传反馈。固定 12 秒窗口按 `Σ丢失 / Σ(接收 + 丢失)` 计算比例，并合并控制消息重传；客户端报告可能包含多种媒体或经过限幅。视频回程保持设备直达，实际视频码率、帧率与端到端延迟继续以客户端观测为准。

初始建议要求至少 6 秒跨度、连续 6 个完整秒都有有效反馈、每秒至少 50 个媒体包且合计至少 600 个。每秒报告丢失达到 3%，或每秒达到 1% 且至少两个秒内出现坏帧／关键帧请求时，建议试用下一低档：200 → 100 → 65 → 45 → 35。阈值属于初始参考，需要 R66S / Portal 实测校准；瞬时波动继续积累证据。

建议保持只读，并绑定中继已观察到的当前档位新连接请求。增强启动前已经建立的串流先采集质量并提示重连。用户在码率配置中选择推荐档位并保存，重连 Portal 后比较相同游戏场景。35 Mbps 持续异常时优先改善无线信号与 AP 争用；连接测试仅采集。新握手重置客户端窗口，反馈中断超过 5 秒会重新积累证据；断开、格式待适配、样本不足和过期数据分别展示。

Linux 每 2 秒读取当前接收套接字的 `PACKET_STATISTICS`，丢包与客户端报告分开统计；中继队列丢包或超过 5% 的转发处理样本耗时达到 5 ms 时，优先提示检查路由器负载与并行任务。处理 p95 使用固定直方图上界估算，覆盖收包后到发送及采集完成的用户态耗时，套接字等待、Wi-Fi 空口与完整串流延迟各有独立测量范围。

采集只保留固定大小的内存窗口与去重键，状态由既有后台队列每 2 秒写入。采集异常时转发与恢复继续运行。增强诊断仅导出聚合计数与建议；原始载荷只用于当次识别，内存去重标识随进程结束释放，设备配置沿用现有脱敏边界。

```sh
ps-accel configure --bridge br-lan --address 10.0.0.250/24 \
  --ps5 10.0.0.100 --portal 10.0.0.101 --profile 65
ps-accel baseline
ps-accel try --seconds 90
ps-accel stop
ps-accel profile --profile 100
```

## 透明代理

进入 **服务 → PS Accel → 透明代理**。插件使用本机 PassWall 的设备访问控制与独立分流规则组，仅绑定“设备配置”中确认的 Portal / PS5 MAC；两台设备共用一组名单。Xray、Sing-box 的配置生成、DNS 和转发由 PassWall 原生处理。

1. 在“代理出口”选择本机已有的 Xray / Sing-box 节点，普通协议与节点附加设置交给 PassWall 处理；分流节点使用其中的实际出口。
2. “代理域名”与“直连域名”初始为空，按实际需要填写，或从域名监控逐项加入、移出。每行完整域名按精确主机名匹配，写入专属分流时生成 `full:` 规则；`domain:example.com` 显式覆盖主域与子域，已保存的设备名单、注释与 `geosite:` 条目保留。
3. “保存设备草稿”只保存本插件的名单。“应用设备规则”创建或更新设备专属访问控制与分流组，再调用 PassWall 重新加载。直连名单优先，代理名单引用所选出口，其他流量默认直连；局域网地址单独直连。
4. “两设备全部直连”保留设备访问控制并让这组流量直接通过。“解除设备接管”删除插件所属访问控制和分流配置，两台设备恢复原 PassWall 策略。

配置使用固定归属标识：访问控制 `ps_accel_devices`、分流节点 `ps_accel_device_shunt`、规则组 `ps_accel_devices`。插件保存到 `/etc/ps-accel/device-proxy/`，两份初始名单均为空，域名来源为用户编辑和已保存的设备规则。独立规则与其他设备的访问控制保持分离；所属规则组被其他配置引用时，先在 PassWall 整理引用，再修改或解除接管。

节点通过完整 UCI 快照读取，支持多行分流规则、节点备注和列表字段。出口类型使用 PassWall 原生的 `Xray` / `sing-box`，Xray 负载均衡和 Sing-box 自动选择交给对应核心处理；切换出口时同步更新设备分流核心。

兼容单节点与 TCP / UDP 分别配置的访问控制格式。全局访问控制总开关原为关闭且存在其他启用规则时，页面提示先在 PassWall 整理配置；启用本组所需的总开关由插件记录，解除接管时按其他规则的当前使用情况恢复。设备身份更换前先解除设备接管。

应用在临时 UCI 配置副本中生成、校验并提交，再检查设备身份、草稿和 PassWall 配置版本后原子写回。并行外部修改会提示重新读取。重载或取消失败时，仅恢复插件所属配置；PassWall 自身的运行记账与其他配置保留。临时副本结束后删除。

**应用通常需要 PassWall 重新加载，现有连接可能重连。** 全局代理关闭时，本组可通过访问控制单独运行；全局代理已配置且服务被手动停止时，配置留待用户在 PassWall 启动后加载。PassWall 的开机启动与 IPv6 转发沿用本机设置。

域名监控继续按连接批次记录解析、失败与流量历史。加入代理、移出转直连只调整设备草稿，应用设备规则后生效；复制输出每行纯域名，可用于 PassWall 普通名单。专属分流使用 `full:` 精确语法。

流量读取本机已有连接接口，优先采样设备专属核心。Sing-box 可读的回环 Clash API 提供域名、出口与连接字节；Xray 的聚合接口与域名级统计各有数据范围，域名流量等待可用数据源时，DNS、批次记录和名单联动继续运行。卸载会解除插件所属设备接管，并保留设备草稿与历史批次。

## 运行反馈与诊断

“目标码率”表示启动请求，“控制转发”表示 Portal → PS5 的中继流量采样。PS5 → Portal 视频沿用设备直达路径。实际画质与视频吞吐通过真实游戏与设备观测评估。

“导出诊断”生成本地 JSON，包含版本、平台、运行计数、测试有效性、恢复状态、域名清单和失败证据。导出保留公共解析地址，并遮盖本地地址与设备 MAC；原始任务日志与会话报文保留在路由器。

```sh
ps-accel status
ps-accel doctor
ps-accel stop
ps-accel repair
logread -e ps-accel
```

`ps-accel stop` 会等待主控、引擎与恢复进程退出，完成恢复后返回。procd 保留独立恢复进程的时间窗口；错误状态会保留恢复路径供检查。

LuCI 停止任务共享 120 秒期限，页面显示停止、等待退出和恢复清理阶段。清理失败后任务进入失败状态，错误原因保留在页面和诊断中；“恢复网络”会再次校验仍存在的命名空间及接口归属，从中断步骤继续。状态查询出错时，停止与恢复入口仍可重试。

动态状态每 3 秒刷新，命名空间存在时执行一次有 2 秒期限的进程查询。配置与基线在首次加载、操作后或配置、程序变化时重新读取校验；启动前执行完整基线校验。各功能的日志阶段可见时按所选类型读取：设备、增强和代理任务输出分别保存，中继事件末尾最多 12000 字节，域名视图读取有界快照。简洁模式每 10 秒刷新日志，详细模式每 2 秒刷新日志；状态继续每 3 秒刷新。

转发循环把事件和统计快照提交到内存队列，后台线程负责文件写入。日志队列保留 128 条，每条最多 4096 字符；积压时舍弃旧记录，统计快照持续合并为最新值。事件日志每份最多 1 MiB，保留 2 份备份，路径为 `/tmp/ps-accel/events.log`。关闭中继时，诊断线程最多等待 0.2 秒。

“增强状态”依据进程启动身份、命名空间和本次启动的就绪标记。“记录状态”展示日志与统计的健康信息；写入失败或采样陈旧时，已就绪的中继继续显示运行，采样值显示为延迟。设备恢复凭据、恢复标记与引擎就绪信息由控制流程同步保存，保存失败时启动流程完成清理并报告错误。

## 域名监控、日志策略与失败回溯

在“码率增强 → 日志与诊断 → 日志设置”或“域名监控 → 域名采集设置”选择详细程度并保存。默认 **简洁** 模式保留中继启停、码率修改握手和异常，重复事件按分钟合并，中继统计快照每 10 秒更新；**详细** 模式每 2 秒更新中继快照，保留每次可见域名事件。域名监控与流量快照每 2 秒更新，日志策略由后台刷新，保存后在 10 秒内应用，中继保持运行。

**“记录 Portal / PS5 域名解析与连接批次”是独立采集开关，默认开启。** 修改开关后点击“保存采集设置”：关闭时释放采集套接字，观察进程进入空闲状态，已有连接批次、域名清单和失败记录保留；重新开启后继续采集。该服务独立命名为 `ps-accel-observe`，中继停止期间也能记录设备访问，采集开关与中继开机启动分别管理。

进入“域名监控”，选择本次连接批次，查看域名、查询类型、解析地址与 TTL、DNS 错误码、TCP 握手响应及 TLS 可见证据。首次域名活动自动创建批次，串流启动与断开标记用于区分连接和重连，小型客户端反馈延续活动时间；连续 60 秒无可见活动后归档。连续重试或复现问题前可点击“新建连接批次”，随后发起设备连接。默认自动跟随最近批次，选择历史批次后刷新继续保留该选择。

“全部域名”与“失败解析”快速切换本批次范围。失败解析包含本批次曾出现 DNS 错误、解析观测超时或 DNS 不可达的域名，后续重试成功时保留失败证据；无地址响应与 TCP 建连错误分别展示。“复制全部域名规则”与“复制失败域名规则”覆盖所选批次的完整清单，跨设备去重，每行输出纯域名 `example.com`，可粘贴到 PassWall 普通规则列表及本插件的设备专属透明代理清单。PassWall 分流规则的域名列表支持 `full:` 精确匹配。每项记录提供“加入代理”与“移出代理”，操作后进入透明代理配置应用设备规则。

每个批次内的域名展示核心上传、下载、直连累计、代理上传／下载累计、代理采样速率和活动代理连接数。默认按代理累计从高到低排序，可选择核心总流量或最近出现排序，勾选“仅看本批次代理相关”或“代理累计 ≥100 MiB”缩小范围；本批次曾走代理或曾在代理名单的标记持续保留。累计达到 100 MiB 的代理记录突出显示，便于移出清单并应用设备规则。移出代理的域名转入直连名单，固件下载可单独保留直连；重连后使用新的规则。

本机已有可读连接接口时，流量使用核心的实际连接计数，每次只累加新增字节；核心或观察服务重启、批次切换时，既有连接从相应基线开始，历史批次保留此前累计。统计包含接口可见的 TCP／UDP 连接；设备直达流量单独按设备侧观测评估。Xray 域名级流量等待可用连接数据源，DNS、批次记录和名单联动持续可用。短连接、采样中断、连接起始时间缺失及容量限制会影响覆盖，并显示部分采样提示；核心连接缺少域名且 DNS 归属有多个候选时，流量记入“域名归属待确认”，同时进入批次合计。已有解析历史的流量统计从新的采集样本开始，流量累计按 60 秒合并保存，批次结束与关闭采集时提交保存。

最近最多 32 个批次保存到 `/etc/ps-accel/domain-batches.json`，历史总容量为 768 KiB，每批最多 512 个设备 / 域名组合与 512 条明细；达到容量时优先轮换旧批次、保留异常明细，并展示精简提示。批次开始、结束与采集关闭时提交持久保存，批次内的新域名和计数沿用合并写入策略。累计清单继续保存到 `/etc/ps-accel/domains.json`，可在批次选择器中切换“历史累计清单”。记录按设备 MAC 绑定，设备更换后重新配对。

设备升级前，在“排查标记”填写新版本名并保存，例如 `Portal 升级 4.0`。随后首次出现的域名显示“本轮新增”；更新日志模式或采集开关时，同一标记的起始时间继续保留。此标记用于比较首次观测时间与升级时间。

设备报错时，在“域名监控 → 连接失败回溯”填写错误码或现场描述，点击“记录这次失败”。系统保存失败前 180 秒、后 15 秒的域名证据，按异常次数排列候选域名；成功访问保留为上下文。重复摘要与内存明细合并时，每次异常计数一次；超出明细容量时优先保留异常，并标出精简和覆盖受限情况。中继、恢复与后台管理任务的失败也会自动加入记录。最近 32 次失败持久保存，每次证据最多 64 KiB。

采集在 LAN 网桥使用内核报文过滤，按已配对设备的 MAC / IPv4 地址匹配，IPv6 按 MAC 匹配。内核筛选 DNS、TCP 建连、可见 TLS ClientHello、ICMP 错误，以及配对设备之间的串流控制标记和小型客户端反馈；观察服务使用低优先级、有界缓存、每秒 500 包上限和后台文件写入。域名事件位于 `/tmp/ps-accel/domains.jsonl`，每份最多 256 KiB，保留 2 份备份；高频原始事件保存在内存和 `/tmp`，持久清单合并写入。

诊断依据可见网络证据：DNS 错误码表示解析返回错误；观测超时表示观察窗口内缺少响应；共享 IP 对应多个候选域名。加密 DNS、TLS ECH、分段 ClientHello、硬件加速和采集限速会影响覆盖；HTTPS 内部业务错误需结合设备提示确认。覆盖时间、采集丢弃、解析错误与写入错误显示在域名视图，便于判断证据完整程度。

## 集成到 25.12 固件或 SDK，生成原生 APK

将本目录完整复制到与你的 R66S 固件同版本的 OpenWrt 构建树 `package/ps-accel/`，选择 `Network → ps-accel`，然后执行：

```sh
make package/ps-accel/compile V=s
```

`Makefile` 使用 OpenWrt 的 `BuildPackage`，包格式跟随目标构建树；25.12 的 apk 构建树生成原生 APK。SDK 的固件版本和软件源应与 R66S 当前固件一致。
